# Problem analysis result: AI 주간 피드백이 "지난주"를 다른 주로 헷갈림

- 날짜: 2026-10-25
- 영역: 3단계 AI 주간 피드백(Claude Haiku 5.5), 프롬프트와 입력 데이터
- 관련 커밋: `f973891`
- 관련 코드: `backend/src/main/kotlin/com/jobscheduler/ai/WeeklyFeedbackService.kt`

## 1. 증상
실제 Claude로 10/19~10/25 주 피드백을 받아 보니 말투와 주 표현이 어긋났다.

| 시도 | 결과 문장 | 문제 |
|---|---|---|
| 1차 | "이번 주는 … 3시간 30분을 쓰고", "경력기술서 초안을 … 쓰셨어요" | 끝난 주를 "이번 주"라고 부름, 높임 표현 "-시-" |
| 2차(높임 규칙 추가 후) | "**지난주에는 공부 기록이 없었고, 이번 주에는** 총 3시간 30분을…" | 그 전 주(10/12)를 "지난주", 돌아볼 주(10/19)를 "이번 주"라고 부름 |

숫자(3시간 30분, 87%, 2일)는 모두 정확했다. 문제는 **어느 주를 무엇이라고 부르느냐**였다.

## 2. 원인 분석
1. **1차:** 프롬프트에 "그 주는 이미 끝난 주"라는 정보가 없었다. 모델 입장에서는 받은 주가 "지금 다루는 주"라 "이번 주"라고 불렀다.
2. **2차:** 규칙으로 "끝난 주는 지난주라고 불러"를 넣었는데, 서버가 보내는 입력 JSON에 그 전 주 공부 시간이 **`lastWeekStudy`**라는 이름으로 들어 있었다.
   - 모델은 규칙보다 **데이터의 이름**을 더 직접적인 근거로 읽었다. `lastWeekStudy = 0분`을 보고 "지난주에는 기록이 없었다"고 썼다.
   - 그 결과 돌아볼 주는 "이번 주"로 밀려났다.
3. 높임 표현은 "해요체"만 지정하고 "-시-"를 막지 않아서 섞였다.

## 3. 해결
- 입력 값 이름을 바꿈: `lastWeekStudy` → **`weekBeforeStudy`**(그 전 주)
- 프롬프트 규칙을 데이터 이름과 맞춰 명시
  - `week`가 돌아볼 주이고 이미 끝났다. 그 주는 "지난주"
  - `weekBeforeStudy`는 그보다 한 주 전이라 "그 전 주"
  - 다가올 주는 "이번 주"
  - 높임 표현(-시-, 예: 쓰셨어요)은 쓰지 말고 "썼어요", "했어요"처럼
- 화면 문구도 맞춤: 횟수를 다 썼을 때 "이번 주 피드백은 다 받았어요" → "이 주 피드백은 다 받았어요"

## 4. 검증 (3차)
> 지난주에는 이직 준비 공부를 총 3시간 30분 했고, 기록은 이틀에 걸쳐 남겼어요.
> 다음 주에 해 볼 것: 이번 주에는 평일 저녁 1시간을 고정해서 …

- 돌아볼 주 "지난주", 다가올 주 "이번 주", 높임 없음, 숫자와 일지 반영 정확
- 테스트 방법: "끝난 주만 받기" 규칙 때문에 서버(`ClockConfig`)와 화면(`todaySeoul`)의 날짜를 임시로 2일 옮겨 확인하고, 커밋하지 않고 되돌림. 횟수 제한은 확인용 일지의 `ai_feedback_count`만 DB에서 1로 되돌려 다시 받음

## 5. 배운 점
- **LLM은 규칙 문장보다 데이터의 이름을 먼저 믿는다.** 입력 JSON의 키 이름이 곧 프롬프트다. 상대적인 표현(last, this, next)은 기준이 바뀌면 뜻이 뒤집히니, 키는 기준과 상관없는 이름(`week`, `weekBeforeStudy`)으로 짓는다.
- 규칙은 데이터 키를 직접 가리키며 쓴다("`weekBeforeStudy`는 그 전 주").
- 단위 테스트(가짜 클라이언트)는 숫자와 흐름은 보지만 말투는 못 본다. 프롬프트를 바꾸면 실제 모델로 한 번 받아 본다.
